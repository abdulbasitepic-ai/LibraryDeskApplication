# LibraryDesk — System Architecture

## 1. Overview

LibraryDesk is a web-based Library Management System developed using Java and Spring Boot.

The project was originally developed as a Java console application and was later converted into a web application using Spring Boot, Thymeleaf, Spring Data JPA, MySQL, and Spring Security.

The application allows users to manage books and students, issue and return books, and maintain borrowing records.

The application is deployed using Railway.

---

## 2. Architecture Overview

LibraryDesk follows a layered architecture.

The main flow of the application is:

```text
User
  │
  ▼
Thymeleaf Web Interface
  │
  ▼
Spring MVC Controller
  │
  ▼
Spring Data JPA Repository
  │
  ▼
Hibernate ORM
  │
  ▼
MySQL Database
```

Each layer has a specific responsibility, which makes the application easier to maintain and extend.

# 4. Application Layers

The presentation layer is responsible for the user interface.

LibraryDesk uses HTML and Thymeleaf templates to display information and provide forms for user interaction.

Main pages include:

```text

Books

Issue Book
```

The model layer contains the application's database entities.


# 6. Entity Relationships

LibraryDesk uses relationships between books, students, and borrowing records.

A `BorrowRecord` has a relationship with one `Book` and one `Student`.

Conceptually:

```text
Book
  │
  │
  ▼
BorrowRecord
  ▲
  │
  │
Student
```

The relationship can be represented as:

```text
Book 1 ──────── * BorrowRecord
Student 1 ───── * BorrowRecord
```

This means a book can appear in multiple borrowing records over time, and a student can have multiple borrowing records.

The `BorrowRecord` acts as the connection between a student and a book.

# 9. Book Issue Flow

When a user issues a book, the application follows this process:

```text
User selects Book
       ↓
User selects Student
       ↓
POST /issue
       ↓
Controller receives request
       ↓
BookRepository finds Book
       ↓
StudentRepository finds Student
       ↓
Check available copies
       ↓
Decrease book copies
       ↓
Create BorrowRecord
       ↓
Save BorrowRecord
       ↓
Save updated Book
       ↓
Display result
```

The borrow record stores the issue date and due date.

---

# 10. Book Return Flow

When a user returns a book:

```text
User selects Borrow Record
       ↓
POST /return
       ↓
Controller receives request
       ↓
Find BorrowRecord
       ↓
Find associated Book
       ↓
Increase available copies
       ↓
Calculate late fee if required
       ↓
Set return date
       ↓
Update BorrowRecord
       ↓
Save changes
       ↓
Display result
```

This ensures that returned books become available again.

---

# 11. Late Fee System

Borrow records contain a `lateFees` field.

The system can calculate a late fee based on the difference between the due date and return date.

Conceptually:

```text
Late Days = Return Date - Due Date

Late Fee = Late Days × Fee Per Day
```

If the book is returned on or before the due date, the late fee is zero.

# 13. Spring Security

Spring Security is included in the application to provide security features.

One important security feature used by LibraryDesk is CSRF protection.

Forms that perform POST requests include a CSRF token.

Example flow:

```text
User submits form
       ↓
Spring Security checks CSRF token
       ↓
Token valid
       ↓
Request reaches Controller
```

This helps protect state-changing requests against Cross-Site Request Forgery attacks.

---

# 14. CSRF-Protected Forms

POST forms such as:

```text
Add Student
Issue Book
Return Book
```

include a CSRF token generated by Spring Security.

The token is included in the HTML form using Thymeleaf.

Conceptually:

```text
HTML Form
    ↓
CSRF Token
    ↓
Spring Security
    ↓
Controller
```

If the token is missing or invalid, Spring Security can reject the request.

# 18. Deployment Architecture

LibraryDesk is deployed using Railway.

The production architecture is:

```text
                   Internet
                      │
                      ▼
              ┌───────────────┐
              │    Railway    │
              └───────┬───────┘
                      │
          ┌───────────┴───────────┐
          │                       │
          ▼                       ▼
┌──────────────────┐   ┌──────────────────┐
│  LibraryDesk     │   │      MySQL       │
│  Spring Boot     │──▶│     Database     │
└──────────────────┘   └──────────────────┘
```

The Spring Boot application runs as one Railway service while MySQL runs as another Railway service.

The application connects to MySQL using Railway environment variables.
